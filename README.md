# E-commerce core (ДЗ 14.2 — режимы доступа)

Проект на **Poetry**: виртуальное окружение, линтер **flake8**, форматер **black**, тесты **pytest** с отчётом покрытия (**pytest-cov**).

## Реализованный функционал (задание 16.2)

- **`BaseProduct`** — абстрактный базовый класс товаров (`new_product`, `price`, `check_change_price`, `__add__`).
- **`PrintCreationMixin`** — миксин, выводящий в консоль класс и параметры при создании объекта; подключён к **`Product`**.
- **`Smartphone`** и **`LawnGrass`** — наследники только **`Product`**.
- **`BaseEntity`** — общий абстрактный класс с свойством `name` для **`Category`** и **`Order`**.
- **`Order`** — заказ с одним товаром, количеством и итоговой стоимостью (доп. задание).

## Реализованный функционал (задание 17.1)

- В `Product.__init__` добавлена проверка количества: при `quantity == 0`
  выбрасывается `ValueError` с сообщением:
  `Товар с нулевым количеством не может быть добавлен`.
- В `Category` добавлен метод `middle_price()` для расчета среднего ценника
  товаров категории.
- Для пустой категории в `middle_price()` обработан случай деления на ноль,
  метод возвращает `0.0`.
- Добавлены тесты для новой функциональности и сохранена совместимость
  предыдущих тестов.

## Реализованный функционал (задание 14.2)

- Класс **`Category`**: приватный список товаров, метод **`add_product()`**, геттер **`products`** (`@property`) — строка с товарами по шаблону.
- Класс **`Product`**: приватная цена, геттер/сеттер **`price`** с проверкой; класс-метод **`new_product()`** (объединение дубликатов по имени — доп. задание).
- Сеттер цены при понижении запрашивает подтверждение **`y`** / **`n`** (доп. задание).
- Функция **`load_categories_from_json`** из ДЗ 14.1: читает `data/products.json`.

## Запуск

```bash
poetry install
poetry run python main.py
poetry run pytest
poetry run flake8 src tests main.py
```

Отчёт о покрытии: каталог `htmlcov/` (откройте `index.html` в браузере).

## GitFlow

Рекомендуемый порядок перед сдачей:

1. Создать ветку `develop` от `main` (если её ещё нет в удалённом репозитории):  
   `git checkout -b develop` и запушить.
2. От `develop` создать feature-ветку, например `feature/14.1-oop-intro`.
3. После коммитов открыть **pull request** из feature-ветки в `develop` (или по инструкции наставника).
